Phase 12 — Charts, indicators and plain-language explanations. Read docs/CLARIX_SPEC.md (§8 comparison page, §12 design system incl. ChartCard / chart_spec rule, charts and animation sections) and replit.md first. Build ONLY this phase.

Goal
Anyone, without training, understands the comparison within seconds: simple charts, clear indicators, short plain sentences, gentle animation. Code calculates; charts only DISPLAY server-computed values. No metric is calculated in the browser. No AI in this phase.

1. Data contract
 - The server returns a chart_spec for each chart (title, unit, series, values, labels, status, source references). Charts must use exactly the same values as the table. Add a test that fails if a chart value differs from the corresponding table value.
 - Missing or blocked values are NEVER drawn as zero. The bar or point is omitted and the card shows "Not available" with the reason and a link to Data Quality.

2. Comparison page charts (two charts only)
 - Chart 1: Scrap rate, Run A vs Run B (bars, axis starts at zero, value labels, % unit). A clear callout of the difference in percentage points (e.g. "+5 pp").
 - Chart 2: Changeover time in minutes (with hours in the label), Run A vs Run B. Unplanned downtime is shown as a SEPARATE small chart or panel with its own title, never stacked on or added to changeover, with the standing non-causal note.
 - Clicking a bar or value opens the existing Source Drawer for that number.
 - Each chart has: a one-sentence plain-language caption generated by fixed templates from the computed values (not AI, facts only, no causes); a "How to read this" tooltip; a visually-hidden data table equivalent for screen readers; and a status badge (word + icon, not colour alone).

3. Indicators (reusable, server-driven)
 - KPI card: big value, unit, small change chip with arrow AND sign AND words (e.g. "▲ +5 pp higher than Run A"), status badge. Never colour alone. Never imply good or bad unless a factory target exists (targets are NOT built yet), so use neutral wording such as "higher" / "lower".
 - Use KPI cards on the Comparison page (scrap rate, good rate, changeover, downtime) and on Overview.
 - Overview: add ONE small chart, a horizontal stacked bar of current orders by status (OK / Check / Blocked) with counts and a short caption. Only server values.

4. Explanations
 - A short glossary (AR + EN): scrap rate, good rate, material balance, changeover, unplanned downtime, percentage point, Not available, Blocked/Check/OK. Show them as small "?" tooltips next to each term wherever the term appears, keyboard accessible, and also list them on the Help page.
 - A "How was this calculated?" link under each KPI that opens the Source Drawer.
 - Keep sentences short and plain, in both languages.

4b. Animation
 - Gentle entrance animation (bars grow from zero, values count up, 300-600 ms) and subtle hover/focus feedback.
 - Respect prefers-reduced-motion: no animation at all in that mode, values shown immediately. Never animate in a way that delays reading the value. Add a test for reduced motion.

5. Design
 - Follow the design tokens and the chart rules in the spec: a validated colour palette that works in light and dark and is distinguishable by more than colour (labels, patterns or position), direct value labels instead of legends where possible, no 3D, no pie/donut, no dual axes, no truncated axes for bars.
 - RTL: chart order, axis labels and numbers read correctly in Arabic; numerals follow the app setting. 360/768/1280px; on phones charts remain readable (bigger touch targets, labels not overlapping).
 - Light + dark. Loading skeletons, empty and error states.

6. Tests (isolated target; do not write to Ethmar/Najm dev data; show before/after counts)
 - For ALL 25 Ethmar scenarios plus Najm: chart values equal table values equal expected_results.json. Scenario checks: 07 (scrap chart shows Not available, changeover chart still drawn), 05/10 (blocked scrap chart), 23 (changeover not comparable, downtime still shown), baseline (5% vs 10%, +5 pp; 240 vs 360 min; downtime 45 separate).
 - No zero is drawn for any missing value.
 - Reduced-motion test; keyboard access to tooltips and drawer; accessible data table present.
 - Screenshots at 360/768/1280px, Arabic/English, light/dark for Comparison and Overview. If the test driver fails, list exactly which are missing; never report a partial set as complete. State clearly that you cannot judge visual quality.

Do NOT build: PDF/export, AI, snapshots, reconciliation, targets/benchmarks, trends over time, extra charts.

Final report: built / not built, test table, before/after counts, and exact manual steps for me.
