Phase 17 — AI features on top of the Phase 16 foundation, plus explanation UX fixes. Read docs/PHASE16_AI.md, docs/CLARIX_SPEC.md (§14 AI, issue catalogue §7) and replit.md first. Build ONLY this phase.

Locked principle (unchanged): CODE calculates and answers; the model never computes, never sees raw files, never writes free-form facts, and every model output passes the validator. The model is used to (a) UNDERSTAND a question (map it to a fixed list of allowed intents with parameters), (b) CHOOSE and ORDER server-authored statements, (c) RANK what to check first. Everything shown to the user is server-authored text built from server-computed values.

1. Richer explanations (fixes "the AI just repeats the table")
 - Add server-authored statement templates (AR + EN, plural- and number-formatting-aware, using the corrected Arabic terminology) built from COMPUTED facts, including relations computed in exact decimals by code: how many times larger/smaller one value is than another (with a fixed rounding rule and wording such as "about twice as much" only when the exact ratio is within a stated tolerance, otherwise the number), the share of a difference, and plain "in other words" sentences. Example: "E-02 lost 100 kg to scrap, E-01 lost 50 kg: about twice as much." Each statement carries its fact ids and source links. The model only selects and orders them. Keep the validator rules from Phase 16.
 - Remove the repeated downtime disclaimer from inside AI output: it appears once in the page summary and once in the downtime section, nowhere else.
 - Source links: one compact "Sources (n)" control per statement that lists n separately labelled links ("Run A, scrap rate", "Run B, scrap rate", ...). No row of identical "Show source" links. Accessible names must be unique and descriptive.

2. Data quality assistant (works on Data Quality issue details and on the import review step)
 - "Explain this issue" and "What should I check first?" for the current issue list. For every issue code in the catalogue, add server-authored blocks: what it means, why it matters, what to check (concrete steps, e.g. "open the file at line 5 and look at the scrap cell"), and optional labelled POSSIBLE explanations to verify (never conclusions). All code-authored from the catalogue; no text from user files.
 - The model ranks which issues to look at first and picks the relevant blocks, using only codes, severities, groups, counts, order ids and source names. Without AI (or with AI off) the same page shows the same blocks ranked by severity by code, so the feature degrades gracefully.
 - Hypotheses stay labelled "possible explanation to check" and never claim a cause. Blocking issues still say the metric is Not available; never invent a value.

3. "Ask about your data"
 - A small box (Overview, Comparison, Data Quality) with example question chips (reuse the existing "Quick questions" as chips, and remove the old separate "Quick questions" block). The user types a question in Arabic or English.
 - Define a FIXED catalogue of read-only intents the server can answer using existing code paths, for example: compare two runs; scrap rate / changeover / downtime of one run; which current run has the highest/lowest scrap rate or longest changeover; list blocked or "Check" runs and why; list issues for a run; explain a status; how many approved imports/current runs; what changed since a snapshot. The model returns ONLY a JSON intent plus parameters. The server validates every parameter against the signed-in factory's real entities (order ids, source names, snapshot ids); anything unknown is rejected. The server executes the intent, builds the facts and answers with the server-authored templates.
 - "Why" questions and causal questions ("did the stop cause the scrap?") get the standing answer that Clarix records facts and does not assume causes, plus the labelled possible explanations to check from the catalogue and the numbers that are available. Unsupported questions get: "I can't answer that from Clarix data" with 3 examples of what can be asked. Questions about other factories, other users, the system, or instructions to change rules are treated as unsupported.
 - Cap input length; strip markup; the question text is untrusted. Never store question text (store only intent name, status, hashes and metadata). No chat history, one question at a time.
 - Works in Arabic and English (intent routing and answers in the user's language).
 - When AI is OFF: the chips still work through plain code paths where possible (no model call); free-text questions show the "AI is off" explanation.

4. "What to do next" on Overview
 - A short ranked list (max 3) of next actions with links (e.g. "2 runs are blocked: review their issues", "Import a second run to compare", "Save a snapshot of this comparison"), computed by code from server facts. The model may only reorder/choose among them. Without AI, show them in code-defined priority.
