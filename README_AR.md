# حزمة Clarix — دليل سريع

## شو في داخل الحزمة؟

| الملف / المجلد | الوظيفة |
|---|---|
| `replit.md` | قواعد قصيرة يقرأها Replit Agent تلقائيًا في كل مرحلة |
| `docs/CLARIX_SPEC.md` | **المواصفات الكاملة** (بالإنجليزي لأن الـ Agent يفهمها أدق): المنتج، القواعد المقفلة، الحسابات، جودة البيانات، التصميم، الأمان، الـ AI، وخارطة المراحل |
| `docs/SCENARIO_CATALOG.md` | جدول بكل سيناريو بيانات: شو الخطأ فيه وشو لازم يسوي التطبيق |
| `docs/TENANCY_TESTS.md` | 12 اختبار لعزل المصانع |
| `test-data/ethmar-plastics/` | بيانات Ethmar: `00_baseline` (الحالة النظيفة من الصورة) + 24 سيناريو فيه أخطاء متعمدة |
| `test-data/najm-packaging/` | مصنع ثاني بصيغة CSV مختلفة (فاصلة منقوطة، فاصلة عشرية، تواريخ dd/mm/yyyy، أطنان) ورقم تشغيلة `E-01` مطابق لاسم تشغيلة Ethmar لاختبار العزل |
| `expected/expected_results.json` | **مفتاح الإجابات**: النتائج الصحيحة مكتوبة يدويًا لكل سيناريو |
| `tools/reference_calc.py` | تطبيق مرجعي صغير للقواعد |
| `tools/verify.py` | يقارن المرجع بمفتاح الإجابات ويتأكد أن الملفات ما تعدلت |
| `tools/generate_test_data.py` | يعيد توليد كل الملفات |

## الحالة الأساسية (Ethmar، من الصورة)

- E-01: مدخل 1000، جيد 950، هدر 50 → **5%**، تغيير قالب **240 دقيقة** (4 ساعات)
- E-02: مدخل 1000، جيد 900، هدر 100 → **10%**، تغيير قالب **360 دقيقة** (6 ساعات)، وتوقف غير مخطط **45 دقيقة** بحدث منفصل
- الفرق: **+5 نقاط مئوية** و **+2 ساعة**

## كيف تستخدمها مع Replit

1. أنشئ مشروع جديد، وارفع محتوى الحزمة كما هو (حافظ على أسماء المجلدات).
2. شغّل `python3 tools/verify.py` وتأكد أنه يطبع `ALL 52 CHECKS PASSED`.
3. بعدها نبدأ **Prompt رقم 1** (الأساس والتصميم) حسب خارطة المراحل في آخر المواصفات (القسم 16). كل مرحلة بـ Planning Mode ثم نراجع الخطة ثم نوافق.
4. من المرحلة 3 وطالع: خلي الـ Agent يحوّل `expected_results.json` إلى اختبارات آلية داخل التطبيق نفسه.

## مهم تعرفه (بصراحة)

- **البيانات مصنوعة بالكامل** بناءً على الحالة اللي بالصورة. أسماء الأعمدة وصيغة الملفات من تصميمي، مش من نظام Ethmar الحقيقي. أول ما يتوفر ملف حقيقي، نضيف له mapping ومجلد جديد، ولا نغير القواعد.
- نجاح `verify.py` يثبت أن **مفتاح الإجابات يتطابق مع القواعد المكتوبة** (جربت تخريب الإجابات والملفات عمدًا وتأكدت أنه يفشل). لا يثبت أن تطبيق Replit صحيح، هذا يثبته اختبار التطبيق نفسه على نفس المجلدات.
- قرارات أنا اتخذتها وبتقدر تعدلها قبل ما نبدأ البناء:
  - حد تحذير عدم توازن المواد **1%** وحد الخطأ **5%** (قابلة للضبط لكل مصنع).
  - تكرار سجل إنتاج مشتبه فيه (id مختلف ومحتوى مطابق) = **أحمر** ويمنع المقارنة حتى مراجعة بشرية؛ أما حدث توقف مشتبه فيه = **أصفر** مع عرض الرقمين (90 أو 45).
  - وحدة غير معروفة مثل `pcs` أو `ton` الملتبسة = غير متوافقة، والمقارنة مرفوضة.
  - التوقيتات بتوقيت المصنع المحلي بدون تحويل مناطق زمنية في النسخة الأولى.
- أشياء غير مغطاة بالبيانات التجريبية ومذكورة بالمواصفات (القسم 15): أرقام غير قابلة للقراءة، ملفات Excel، ملفات ضخمة، والواجهة نفسها.
- اسم **Clarix**: تأكد من توفره كاسم تجاري ودومين قبل أي إطلاق عام.
